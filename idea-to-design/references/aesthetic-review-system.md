# Aesthetic Review System

Use after image generation and before accepting visuals for high-fidelity or final design reference.

## Lightweight Review

Check:

- context fit
- audience fit
- readability
- one memorable move
- real content quality
- anti-AI-slop risk
- implementation feasibility

If the page is not core, keep the review to 3-5 bullets.

## Anti-AI-Slop Check

Reject or revise if the output relies on:

- big headline, subtitle, and three equal cards as the whole concept
- empty dashboard numbers without believable content
- generic purple/blue gradients
- random glassmorphism with no product reason
- decorative blobs, waves, or 3D objects that do not support meaning
- low-contrast gray text and flat white cards
- every page using the same hero-plus-cards composition
- visible placeholder or annotation-like UI copy

## Design Maturity Ladder

Rate the result:

- `generic`: template-like, reject for core pages.
- `competent`: usable but ordinary, acceptable for support pages.
- `distinctive`: clear, credible, with a memorable move; default target for core pages.
- `excellent`: strong context fit, strong craft, useful visual identity, feasible to build.

Core pages should reach at least `distinctive` before high-fidelity confirmation.

## Novelty Without Fragmentation

Allow variation in:

- page composition
- visual hook
- illustration or imagery treatment
- content rhythm

Keep stable:

- visual DNA
- CTA hierarchy
- basic component personality
- typography system
- accessibility and readability

## Aesthetic Regression Check

When generating later pages, check whether the result:

- became more generic than the approved direction
- lost the visual DNA
- copied a previous page composition too mechanically
- chased trend at the cost of trust
- became harder to implement than the value justifies

## Design Critique Loop

After each important image round, record:

- keep
- remove
- biggest issue
- next single change goal
- maturity rating

Change one main goal per next prompt.
